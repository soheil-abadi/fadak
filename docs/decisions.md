# تصمیم‌های فنی و محدودیت‌ها

این تصمیم‌ها در نسخه فعلی اجرا شده‌اند. شاهد build و تست‌ها در [گزارش بررسی](verification.md) ثبت می‌شود؛ همه سناریوهای برنامه تحویل الزاماً آزموده نشده‌اند. معیار انتخاب، پوشش نیازمندی‌های شرکت در بودجه ۸ تا ۱۲ ساعت، امکان توضیح تصمیم‌ها و کاهش ریسک تاریخ و state است. [قراردادها](contracts.md) مرجع جزئیات رفتار و [معماری](architecture.md) مرجع مرزبندی کد هستند.

## وابستگی‌ها و منابع رسمی

نسخه‌های دقیق در package.json و package-lock.json ثبت شده‌اند: Next.js 16.4.5، React و React DOM 19.3.1، TypeScript 5.9.3، Tailwind CSS 4.3.5، React Hook Form 7.91.0، Zod 4.6.7 و react-multi-date-picker 4.5.2 با react-date-object 2.1.9. محیط بررسی Node 22.22.1 است. بسته‌ها beta یا canary نیستند و نصب از lockfile انجام می‌شود. نسخه مستقیم react-date-object چون در کد import می‌شود ثبت شده است و صرفاً به وابستگی transitive تکیه نمی‌شود.

## ملاحظات Next.js و کش

خواندن searchParams وابستگی نتیجه به درخواست را مشخص می‌کند؛ شکل API مانند Promise بودن params و searchParams باید با نسخه منتخب هماهنگ شود. فرضیات قدیمی درباره cache پیش‌فرض از نمونه‌های اینترنتی کپی نمی‌شوند. برای provider خارجی، no-store صریح است؛ `revalidate` متناقض به همان درخواست اضافه نمی‌شود. Mock هیچ fetch HTTP ندارد و با آن سیاست یکی فرض نمی‌شود.

کش مرورگر، Router Cache، memoization یک render و persistent Data Cache مفهوم یکسانی ندارند. در build production، تغییر query، Refresh و تلاش مجدد باید داده مربوط به همان جست‌وجو را نشان دهند. در این نسخه Cache Components یا کش عمومی سفارشی فعال نمی‌شود. جزئیات بررسی و نسخه دقیق پس از ساخت به همین سند افزوده خواهد شد.

## محدودیت‌های پذیرفته‌شده

- build و بررسی‌های ثبت‌شده در گزارش بررسی اجرا شده‌اند؛ امتیاز رسمی عملکرد، آزمون با صفحه‌خوان واقعی و انطباق کامل WCAG سنجیده نشده‌اند.
- داده‌ها ساختگی و ظرفیت Mock ثابت‌اند؛ قیمت و شرایط هتل واقعی را نمایش نمی‌دهند. مدل ساده ظرفیت و افق تاریخ در قراردادها تعریف شده است.
- نتیجه‌ها کوچک و بدون صفحه‌بندی‌اند. جایگزینی provider قابل طراحی است، ولی ترکیب هم‌زمان چند provider و رفع رکورد تکراری ساخته نمی‌شود.
- تقویم بر قرارداد ماژول persian در نسخه انتخابی تکیه دارد. اختلاف الگوریتم‌ها و کنترل صفحه‌کلید باید آزمون و نتیجه ثبت شوند.
- پیش‌نمایش رزرو هیچ موجودی را قفل نمی‌کند، پرداخت ندارد و شماره رزرو معتبر ایجاد نمی‌کند.
- Deploy انجام نشده و اعداد عملکرد رسمی وجود ندارند. تصاویر واقعی اجرای محلی در گزارش بررسی ارائه می‌شوند.

## بهبودهای مناسب Production

پس از تکمیل نسخه آزمون، اولویت‌ها شامل اعتبارسنجی قرارداد provider واقعی، timeout و لغو شبکه، سیاست تازگی قیمت، کنترل تغییر نرخ پیش از رزرو و پایش خطا با شناسه درخواست است. سپس مدل مالیات و کنسلی، ظرفیت واقعی و سن مسافر، rate limit و بررسی امنیت ورودی و دارایی‌ها تکمیل می‌شوند.

در تجربه کاربری، تقویم و modal با صفحه‌خوان و کاربران واقعی بررسی می‌شوند. در مقیاس بزرگ‌تر، صفحه‌بندی و اندازه‌گیری bundle و Web Vitals بر اساس داده واقعی بررسی خواهد شد. این موارد برنامه توسعه محصول‌اند و برای نمایشی‌کردن تسک به محدوده فعلی وارد نمی‌شوند.

## سازگاری ابزارها در محیط بررسی

در sandbox، Turbopack هنگام تبدیل CSS برای پردازش PostCSS به bind محلی نیاز داشت و متوقف شد. به همین دلیل اسکریپت‌های توسعه و build از Webpack استفاده می‌کنند. Next.js 16.4.5 در مسیر پیش‌فرض CLI TypeScript، فرایند جداشده‌ای اجرا می‌کرد که در این محیط stdout قابل دریافت نداشت؛ تنظیم `experimental.useTypeScriptCli: false` از API کامپایلر TypeScript نصب‌شده استفاده می‌کند. بررسی TypeScript در build و اسکریپت مستقل typecheck هر دو فعال‌اند.

ESLint 9.39.5 با peer dependencyهای پلاگین‌های lint نصب‌شده Next.js سازگار است؛ ESLint 10 در برخی از همان پلاگین‌ها هنوز peer پشتیبانی‌شده نبود. شاخه ۹ هشدار پایان پشتیبانی دارد. این انتخاب و advisory توسعه در گزارش بررسی ثبت می‌شوند و پیش از نگهداری بلندمدت باید دوباره بررسی شوند؛ از force برای downgrade نامرتبط Next.js استفاده نشده است.

وضعیت موقت navigation در یک Context سبک Feature بین کنترل‌ها مشترک است. این Context فقط pending و عمل navigation را می‌دهد و Store داده محصول نیست. سرور همچنان منبع داده و URL منبع جست‌وجوی ثبت‌شده است.

در smoke test توسعه، Next.js به‌صورت پیش‌فرض یک بلوک انگلیسی به AGENTS.md اضافه می‌کرد. مقدار `agentRules: false` برای حفظ قواعد فارسیِ تحت کنترل پروژه تنظیم شد. فایل next-env.d.ts تولیدشدنی است و با تغییر dev/build مسیر importهایش عوض می‌شود؛ در Git نگهداری نمی‌شود و هنگام اجرای Next دوباره تولید خواهد شد.

در بازبینی صفحه‌کلید، ورودی پیش‌فرض تقویم با Enter باز نمی‌شد و ویژگی‌های خطا را به input داخلی منتقل نمی‌کرد؛ render سفارشی محدود با button بومی این مرز را مشخص می‌کند. نام ماه قبل/بعد با رفتار واقعی نسخه نصب‌شده تطبیق داده شد. فلش ماه در مرز بازه از aria-disabled و محافظ عمل استفاده می‌کند تا غیرفعال‌شدن ناگهانیِ عنصر فوکوس‌شده، فوکوس را از بین نبرد. برای این اصلاح‌ها وابستگی جدیدی اضافه نشده است.
