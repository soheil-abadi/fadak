# برنامه ساخت و تحویل جریان هتل

این سند برنامه اولیه ساخت و معیارهای تحویل را نگه می‌دارد؛ وضعیت نسخه ساخته‌شده در [گزارش بررسی](verification.md) ثبت می‌شود. برآورد پایه ۹ ساعت کار مفید و ذخیره رفع اشکال تا ۳ ساعت است؛ زمان مستندسازی فعلی در این برآورد محاسبه نشده است. هدف پیشنهادی سند ۸ تا ۱۲ ساعت است و زمان واقعی باید ثبت شود. کاهش دامنه امکانات اختیاری مجاز است؛ حذف خطا، اعتبار تاریخ یا بازیابی URL راه جبران زمان نیست.

## راهبرد تست متناسب با ریسک

برای منطق خالص، Vitest؛ برای رفتار فرم، React Testing Library همراه user-event؛ برای جریان مرورگر، Playwright انتخاب پیشنهادی این طرح است. نسخه‌ها و سازگاری هنگام ساخت ثبت می‌شوند. خود Server Component با mock کردن تمام Next.js تست واحد نمی‌شود؛ ترکیب مسیر و رندر آن در E2E و production smoke بررسی خواهد شد.

در تست تاریخ، clock تزریق می‌شود؛ تست به روز دستگاه یا شبکه زنده وابسته نیست. در تست سرویس، provider یا تنظیمات factory تزریق می‌شوند؛ env سراسری میان تست‌های هم‌زمان تغییر نمی‌کند. مجموعه تست بر رفتار قابل مشاهده و ریسک واقعی متمرکز است، نه تعداد فایل یا درصد پوشش قراردادی.

## معیار کیفیت ظاهری و تعامل

در دسکتاپ فرم جست‌وجو و خلاصه اقامت بالای نتایج قرار می‌گیرند و فیلترها کنار فهرست هستند. در موبایل، فرم و کارت تک‌ستونه‌اند و فیلترها در بخش قابل باز و بسته‌شدن با کنترل native و برچسب روشن ارائه می‌شوند. کنترل‌ها با ویژگی‌های منطقی CSS برای RTL چیده می‌شوند.

عنوان نتیجه، تعداد یافته‌ها، خلاصه اقامت و فیلترهای فعال باید وضعیت جست‌وجو را روشن کنند. کارت، قیمت هر شب یک اتاق و مبلغ کل را با برچسب جدا نشان می‌دهد. Empty امکان پاک‌کردن فیلتر یا اصلاح جست‌وجو دارد؛ Error دکمه تلاش مجدد دارد. از مؤلفه تزئینی، انیمیشن یا قابلیت اضافی‌ای که زمان رسیدگی به این رفتارها را بگیرد صرف‌نظر می‌شود.

## بررسی‌های نهایی و ثبت نتیجه

پس از ایجاد scriptهای واقعی پروژه، typecheck، lint، تست واحد و کامپوننت، build و سناریوهای E2E اجرا شوند. اجرای production با start همان build بررسی شود؛ موفقیت dev کافی نیست. نصب از lockfile در checkout تمیز، نسخه Node و دستورهای واقعی در README ثبت شوند. اگر CI اضافه می‌شود، همان scriptها را با lockfile ثابت اجرا کند.

قالب شاهد برای هر بررسی:

```text
Requirement: R-15
Scenario: T-14
Revision: actual commit hash or working-tree snapshot identifier
Environment: actual Node, package versions, browser and viewport
Command or steps: exact executed command or reproduction steps
Result: passed / failed / not run
Evidence: actual output or screenshot location
Remaining limitation: concrete limitation, if any
```

قالب بالا فقط قالب گزارش است؛ تا اجرا نشده پر نمی‌شود. screenshot واقعی با فایل یا مسیر موجود ارجاع داده می‌شود. در اصلاح صرفاً متنی، بررسی لینک و هماهنگی قرارداد کافی است و اجرای تست برنامه نیاز نیست.

## چک‌لیست تحویل برنامه

- [ ] README از checkout تمیز قابل دنبال‌کردن و دستورهای آن اجرا شده‌اند.
- [ ] همه نیازمندی‌های الزامی با کد و شاهد، وضعیت به‌روز دارند.
- [ ] جریان هتل، دو فیلتر، دو sort، URL و پیش‌نمایش کامل‌اند.
- [ ] سناریوهای تاریخ و واحد پول و تفاوت empty/error بررسی شده‌اند.
- [ ] تقویم، RTL، نمایش موبایل و صفحه‌کلید با شاهد مرور شده‌اند.
- [ ] typecheck، lint، تست‌ها و build اجرا و نتیجه واقعی ثبت شده است.
- [ ] secret، فایل env خصوصی و داده شخصی وارد Git یا bundle نشده است.
- [ ] محدودیت‌ها، نسخه بسته‌ها و تصمیم‌های فنی مطابق کد هستند.
- [ ] Commitها واقعی و قابل فهم‌اند و داوطلب تغییرات تولیدشده با AI را مرور کرده است.
- [ ] اگر Deploy مجاز و ممکن بود، همان نسخه بررسی و لینک واقعی افزوده شده است؛ در غیر این صورت نسخه محلی قابل اجرا تحویل می‌شود.

## اعتبارسنجی بسته مستندات فعلی

برای تغییر صرفاً مستندات، پیوندهای داخلی، تعداد و وجود فایل‌های توافق‌شده، fenceهای نمونه‌ها، صحت frontmatter و اعتبار Skill بررسی شوند. نمونه JSON و Typeها با هم تطبیق داده شوند و مثال قیمت و URL از نظر معنایی مرور شود. این بررسی‌ها معادل اجرای T-01 تا T-18 یا تأیید برنامه نیستند.
