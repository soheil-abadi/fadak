# گزارش بررسی نسخه محلی

تاریخ بررسی تکمیلی: ۲۰۲۶/۱۱/۰۸ به وقت تهران. این گزارش فقط اجراهای ثبت‌شده و مرور کد همین نسخه را توصیف می‌کند؛ همه سناریوهای برنامه تحویل یا همه مرورگرها تأیید نشده‌اند.

## محیط و شناسه نسخه

| مورد | مقدار |
| --- | --- |
| سیستم | Linux x64 |
| Node و npm | Node 22.22.1 و npm 9.2.0 |
| Framework | Next.js 16.4.5، React 19.3.1؛ Webpack |
| تست | Vitest 5.1.0 و Playwright 1.65.0 |
| مرورگر بررسی | Chrome for Testing 151.0.7922.34؛ Chromium موجود با مسیر صریح |
| تنظیم Mock در E2E | تأخیر ۱۰۰۰ میلی‌ثانیه؛ سناریوهای success، error، timeout و empty در سرورهای جدا |
| Commit منبع بررسی‌شده | `52e4e98b3c3c8fc022bbcd16dd38b568c6c8dfbf`؛ گزارش و اصلاح صرفاً روش ثبت screenshot پس از آن تکمیل شده‌اند؛ کد برنامه تغییری ندارد. |
| شناسه snapshot منبع | `0d9318c06178f7da4436315d6617a73aab4923f7d682c8466cd54fffe0f6c57b` |

شناسه بالا SHA-256 محتوای مسیرهای src، tests و public و تنظیمات build/test و lockfile است؛ فایل‌های گزارش و خروجی build در آن نیستند. این شناسه جای Commit Git نیست. مخزن محلی در همین مرحله ایجاد شده است؛ تاریخچه قدیمی بازسازی نشده و Push یا Deploy انجام نشده است.

## بررسی‌های اجراشده

| بررسی | نتیجه و حدود آن |
| --- | --- |
| `npm ci` | نصب از lockfile موفق؛ فایل env یا API key لازم نبود. |
| `npm run typecheck` | موفق با strict و noUncheckedIndexedAccess. |
| `npm run lint` | موفق بدون warning یا error کد پروژه. |
| `npm run format:check` | موفق؛ فایل تولیدشده next-env.d.ts از formatter مستثناست. |
| `npm test` | ۶۴ تست در شش فایل موفق؛ منطق تاریخ، schema، URL، دامنه، provider و فرم. |
| تقویم در سه timezone | هر ۱۱ تست تقویم در UTC، Asia/Tehran و America/Los_Angeles موفق. این ۳۳ اجرا، تست‌های جدید مستقل به شمارش ۶۴ اضافه نمی‌کنند. |
| `npm run build` | موفق؛ `/hotels` و جزئیات dynamic و ریشه و icon به شکل static تولید شدند؛ TypeScript در build هم بررسی شد. |
| مرورگر success | هشت سناریوی فعال موفق؛ دو سناریوی مختص حالت دیگر عمداً skip شدند. |
| مرورگر error | سناریوی خطای سرویس و retry روی همان URL موفق؛ نه سناریوی نامرتبط skip شدند. |
| مرورگر timeout | سناریوی timeout شبیه‌سازی‌شده و retry روی همان URL موفق؛ نه سناریوی نامرتبط skip شدند. |
| مرورگر empty | پاسخ خالی موفق بدون Error یا دکمه retry تأیید شد؛ نه سناریوی نامرتبط skip شدند. |
| مرز داده سرور | نام تنظیمات HOTEL_MOCK و قیمت خام fixture در فایل‌های JS کلاینت تولیدشده پیدا نشد؛ محافظ server-only نیز در مرز composition و زیرساخت وجود دارد. این بررسی جای ممیزی امنیت جامع نیست. |
| `npm audit --omit=dev` | صفر advisory در وابستگی‌های runtime در بررسی ۲۰۲۶/۱۱/۰۷؛ در دور تکمیلی دوباره اجرا نشد. |

ماتریس اصلی چهار پیکربندی شامل ۱۱ بررسی فعال موفق است؛ تست responsive پس از اصلاح چیدمان و اطمینان از بارگذاری تصاویر نیز جداگانه تکرار شده است. سناریوی failure در هر دو تنظیم error و timeout اجرا شده و دو آزمون مستقلِ متفاوت محسوب نمی‌شود. فایل [تست مرورگر](../tests/e2e/hotel-search.spec.ts) جزئیات قابل تکرار را دارد.

## نصب و اجرای مستقل از checkout تمیز

در ۲۰۲۶/۱۱/۰۸، Commit بالا با clone محلی در `/tmp/fadak-verified.fn5Wyh` بررسی شد؛ پوشه در شروع node_modules، .next و next-env.d.ts نداشت. تلاش نصب offline به علت نبود tarballهای لازم در cache با ENOTCACHED شکست خورد و نصب موفق فرض نشد. نصب بعدی از registry با lockfile ثابت، cache موقت و بدون تغییر وابستگی انجام شد:

```bash
npm ci --cache /tmp/fadak-verification-npm-cache --no-audit
npm run typecheck
npm run lint
npm run format:check
npm test
npm run build
npm run dev -- --port 3270
```

نصب ۴۸۰ بسته، typecheck پیش از نخستین build، lint، formatting، هر ۶۴ تست و build موفق بودند. پس از راه‌اندازی dev، درخواست `/hotels` پاسخ ۲۰۰ داد و متن فارسی، lang=fa و dir=rtl در HTML تأیید شدند. سرور متوقف شد؛ git status --porcelain پس از build و دوباره پس از dev خروجی خالی داشت. next-env.d.ts تولید و توسط Git نادیده گرفته شد. SHA-256 فایل AGENTS.md پیش و پس از اجرا یکسان بود:

```text
175eefbf0f423f2db36ffdeaca413a840d5cf808978a3333f736dcc882334b3a
```

بنابراین R-34 و اصلاح agentRules=false در یک checkout مستقل شاهد دارند. این clone موقت است؛ remote یا انتشار خارجی برای مخزن تحویلی ایجاد نشده است. دستورهای عادی کاربر همچنان در README هستند و cache موقت، پیش‌نیاز اجرای برنامه نیست.

State انتظار navigation میان فرم، فیلتر و sort از یک Context سبک UI به اشتراک گذاشته می‌شود؛ هیچ query یا نتیجه سروری در آن کپی نمی‌شود. این قفل تا commit شدن navigation است و الزاماً تا پایان stream نتایج ادامه ندارد. تست به حفظ مقادیر URL بعد از دو اقدام نزدیک به هم تکیه دارد و حداقل مدت نمایش حالت disabled را فرض نمی‌کند.

## ارزیابی تکمیلی تاریخ و دسترس‌پذیری پایه

- ۹ تست SearchForm شامل هفت regression جدید است: ورود بدون تغییر یا سازگار، پاک‌شدن خروج ناسازگار همراه توضیح، متن ناقص/نامعتبر، Enter پیش از blur، همگامی تقویم و متن، فوکوس خطای تاریخ و جهت درست ماه با حفظ فوکوس در مرز.
- دو سناریوی جدید مرورگر، ورود متنی نامعتبر با Enter و بازکردن تقویم از Tab، جابه‌جایی ماه، Escape و فوکوس را پوشش می‌دهند. سناریوی ماه در عرض‌های ۳۷۵، ۷۲۰ و ۱۴۴۰ اجرا شد؛ تقویم داخل viewport ماند و outline فوکوس قابل مشاهده بود. تصاویر همان اجرا بازبینی شدند.
- مقادیر computed رنگ در مرورگر برای برچسب و راهنمای متنی فرم روی سفید `#647263 / #ffffff = 5.09:1`، دکمه جست‌وجو `#ffffff / #166b5c = 6.38:1` و متن دکمه تقویم `#203c35 / #ffffff = 11.94:1` محاسبه شد. این نمونه‌برداری، ممیزی تمام متن‌ها، تصاویر، gradientها یا همه حالت‌های کنترل نیست.
- عرض ۷۲۰ CSS px، reflow متناظر با پنجره ۱۴۴۰ در بزرگ‌نمایی ۲۰۰٪ را ارزیابی می‌کند؛ شاهد بزرگ‌نمایی واقعی مرورگر نیست. کلید zoom در مرورگر داخلی و تنظیم profile آزمایشی Chromium نسبت devicePixelRatio را تغییر ندادند؛ بنابراین بزرگ‌نمایی واقعی ۲۰۰٪ تأیید نمی‌شود و باید دستی بررسی شود. هیچ تنظیمی در مرورگر شخصی کاربر تغییر نکرد.
- صفحه‌خوان واقعی، پیمایش کامل grid با کلیدهای جهتی و لمس روی دستگاه فیزیکی آزموده نشدند. برخی containerهای داخلی کتابخانه همچنان برچسب انگلیسی «Choose» در درخت دسترس‌پذیری دارند؛ دکمه‌های قابل اقدام فارسی‌اند. این محدودیت‌ها با تأیید کنترل‌های پایه رفع‌شده فرض نمی‌شوند.

## محدودیت و کار باقی‌مانده

- رزرو و پرداخت واقعی، API زنده، موجودی روزانه، مالیات پویا و مدل سن مسافر ساخته نشده‌اند؛ محدودیت عمدی نسخه‌اند.
- آزمون جامع صفحه‌خوان، رفتار پیشرفته grid، همه حالت‌های zoom و لمس واقعی اجرا نشده است. اعداد Lighthouse یا تضمین WCAG ارائه نمی‌شود.
- در بررسی وابستگی‌های ۲۰۲۶/۱۱/۰۷، هشت advisory متوسط در ابزارهای توسعه گزارش شد؛ مسیر اصلی از minimatch و زنجیره TypeScript ESLint بود. شاخه سازگار ESLint 9 نیز هشدار پایان پشتیبانی دارد. runtime audit همان مرحله جداگانه صفر بود؛ نصب تکمیلی با no-audit اجرا شد. برای رفع این مورد باید نسخه‌های سازگار lint با upstream دوباره بررسی شوند؛ force downgrade روی Next انجام نشده است.
- API compiler در Next از طریق تنظیم experimental فعال شده است؛ هنگام ارتقای TypeScript یا Next این انتخاب دوباره بررسی شود. build و typecheck فعلی هر دو موفق‌اند.
- Git remote و Deploy ایجاد نشده‌اند. Commit جاری یک snapshot واقعی از کار انجام‌شده است و سابقه مرحله‌بندی‌شده ساختگی ایجاد نمی‌شود.
- داوطلب باید قبل از ارسال، کد و محدودیت‌ها را مرور کند و بتواند تصمیم‌ها را با بیان خود توضیح دهد.
